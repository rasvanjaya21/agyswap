# AGENTS.md

## What this is

agyswap (`agyswap`) switches between multiple Google accounts for the **Antigravity CLI (`agy`)**.

**Scope:** `agy` only. Do not target the Antigravity IDE (`~/.config/Antigravity/.../state.vscdb`), Gemini CLI, Gemini Code Assist, or any other Google AI product. An earlier version wrongly targeted the IDE.

## Layout

- `src/agyswap/cli.py`: the store, the quota cache (`usage.json`), keyring access, commands (`add`, `list`/`ls`, `status`, `switch`, `alias`, `disable`, `enable`, `auto`, `export`, `import`, `remove`/`rm`, `tui`), account picking (`pick_account`), JSON output, and the rendering shared with the TUI. Running bare `agyswap` in a TTY opens the TUI.
- `src/agyswap/usage.py`: token refresh and quota fetching.
- `src/agyswap/tui.py`: the Textual dashboard. Keys: `enter`/`s` switch, `a` add, `d` remove (confirmed), `x` disable/enable, `r` refresh, `j`/`k`, `q`. The look is a user decision; keep it unless asked: the pitch-black theme (`#000000`), the centered title `agyswap - Antigravity CLI Accounts Swap`, the selected card in solid blue `#0178d4`, the orange accent `#ffa62b` (title, `● active`, footer key badges) on a `#141414` footer aligned with the status line, and the command palette disabled.
- `tests/test_swap.py`: pytest tests using a fake keyring. They never touch the real keyring or the network.

## How agy stores auth (verified on agy 1.3.1, Linux)

The full map, with evidence, is in `architecture/OBSERVE.md`. Summary:

- The token is in the OS keyring via zalando/go-keyring, with `service=gemini` and `username=antigravity`. The value is JSON: `{"token": {access_token, token_type, refresh_token, expiry}, "auth_method", "id_token"}`. The email comes from the `id_token` `email` claim. Access with `secret-tool lookup/store`.
- Quota has two windows per model group ("Gemini Models", "Claude and GPT models"): **5h** and **weekly**. Both come from `POST https://daily-cloudcode-pa.googleapis.com/v1internal:retrieveUserQuotaSummary` with body `{}` (`groups[].buckets[]` with `window`, `remainingFraction`, `resetTime`), which is what agy's `/quota` uses and what `usage.fetch_pools` reads. (`fetchAvailableModels` only reports the 5h window and is no longer used.) Requests need a non-default User-Agent (`antigravity`), because `Python-urllib` gets a 403.
- The hidden flag `--gemini_dir=<dir>` gives agy a fully separate data dir, but the token still comes from the shared keyring item. agy falls back to file token storage when the keyring times out or D-Bus is unreachable; that file's path is not yet observed and not supported. Parallel per-account sessions (a `run` command) are not possible yet.
- A running agy reads the keyring once at startup, then refreshes and re-saves its token hourly. Switching while agy runs never reaches that session and gets overwritten, so automatic switching can only happen between agy sessions.
- Token refresh goes to `https://oauth2.googleapis.com/token`. The client ID is the token's `azp` claim, and the client secret (`GOCSPX-…`) is read from the installed `agy` binary at runtime. Never hardcode or commit it. Google does not rotate the refresh token on refresh.
- `/logout` in agy does **not** revoke the stored refresh token (verified with 2 real accounts). Adding an account works like this: run `/logout` in agy, sign in with the next account, exit, then `agyswap add`.

## Invariants

- Never overwrite a login that has no stored copy. `switch` saves an unstored live login into a new slot first.
- Before switching, copy the live keyring token back into its slot, because agy refreshes tokens hourly.
- `add --slot N` must not clobber a different account. Moving the same account to a new slot is allowed.
- Every store mutation goes through `locked_store()` (flock on `~/.agyswap/.lock`). Usage refresh runs its network fetch unlocked, then merges newer tokens into a fresh read under the lock.
- `~/.agyswap/accounts.json` holds refresh tokens. Write it atomically with mode 0600.
- Refuse to switch while a non-updater `agy` process is running (`--ignore-running` overrides). A running agy re-saves its own token.
- `switch --force` only skips copying the live token back into its slot. It never skips saving an unstored live login.
- `remove` asks `[y/N]` on a TTY (Enter, Ctrl-D and Ctrl-C mean no) and refuses without `--yes`/`-y` otherwise. It reads the keyring once to warn when the account is the active one (a user decision). The TUI uses its own confirmation modal and calls `cmd_remove` directly.
- TUI actions target accounts by email, never by the slot of a possibly stale row, and run `cmd_*` in a thread worker so a locked keyring never freezes the UI. Text from outside (errors, emails) is shown with markup off or `escape()`d.
- Never write the keyring during usage refresh. Only `switch_account` writes it (`switch`, `switch --strategy`, `auto`). `auto` runs once per call and never in the background.
- `usage.json` holds quota only, never tokens. It and `accounts.json` are written by `_write_private` under the same `locked_store()` lock.
- A rejected refresh token (`TokenRevoked`) only disables the account (`disabled_reason: token revoked`), and only if the stored token is still the one that was rejected. Nothing deletes an account except `remove`. `add` lifts a `token revoked` mark but keeps a `manual` one and the alias.
- `export` writes refresh tokens to a new file with `O_EXCL | O_NOFOLLOW` and mode 0600; `import` validates the whole file (each token's `email` claim must match its entry) before writing, and never writes the keyring.
- No exception may escape the TUI. Textual's crash report prints locals, which hold tokens and the client secret. TUI handlers catch `Exception`, show `SwapError` text or the exception type only, and call the UI outside the `except` block so the original error is never chained. `usage._post` turns read-time network errors into `UsageError`, and `_secret_tool` turns a keyring timeout into `SwapError`. A `secret-tool lookup` that fails with stderr is a `SwapError`, not "signed out"; only a silent exit 1 means no login.

## Safety rules for agents

- **Never run** `git push` (branches or tags, including force), `git restore`, `git reset`, `git checkout -- <path>`, `git clean`, `git revert`, `git rebase`, `git stash drop`, `git branch -D`, or `git tag -d`. The user runs these themselves; write the command out for them. Agents may only read (`status`, `diff`, `log`, `show`) and `add`/`commit` through `/agyswap-commit`. This overrides any skill text.

- Do not print token values (access, refresh, id, or client secret). Print key shapes and lengths only.
- Do not enumerate Secret Service items with raw `busctl get-property` loops. That crashed gnome-keyring 48 on this machine (`invoke_get_property_in_idle_cb: assertion failed`). Use `secret-tool`.
- Run manual tests with `AGYSWAP_HOME=$(mktemp -d)`, and shred the temporary `accounts.json` afterwards.

## Dev

```bash
uv sync                 # creates .venv; no need to activate
uv run ruff format . && uv run ruff check .
uv run pytest -q
uv run agyswap          # TUI
uv run agyswap list
uv build                # wheel + sdist into dist/ (gitignored)
uv run python scripts/docs.py   # re-mirror docs/ after a dependency bump
graphify update . && graphify label . --backend=gemini
```

Ruff also formats code blocks inside Markdown, so `[tool.ruff] extend-exclude` keeps it out of the generated or vendored `docs/`, `skills/`, and `graphify-out/`; never drop that exclusion. Python 3.12+ and stdlib, plus `textual` and `rich`. Linux only for now (`secret-tool`, `fcntl`, `pgrep`). The version lives only in `pyproject.toml`; `__init__.py` reads it through `importlib.metadata`. The PyPI distribution is `agyswap-cli` (PyPI rejected `agyswap` as too similar to an existing `agy-swap`); the command and the import package stay `agyswap`.

## Agent workflow

The project cycle, in this exact order:

```
   PREPARE       OBSERVE        DEFINE          PLAN          BUILD          VERIFY         REVIEW        PREPARE        COMMIT          SHIP
┌────────┐     ┌────────┐     ┌────────┐     ┌────────┐     ┌────────┐     ┌────────┐     ┌────────┐     ┌────────┐     ┌────────┐     ┌────────┐
│  Repo  │ ─▶ │  Flow  │ ─▶ │  Idea  │ ─▶ │  Spec  │ ─▶ │  Code  │ ─▶ │  Test  │ ─▶ │   QA   │ ─▶ │ Clean  │ ─▶ │  Git   │ ─▶ │   Go   │
│  Sync  │     │  Map   │     │ Refine │     │  PRD   │     │  Impl  │     │ Debug  │     │  Gate  │     │ Polish │     │ Record │     │  Live  │
└────────┘     └────────┘     └────────┘     └────────┘     └────────┘     └────────┘     └────────┘     └────────┘     └────────┘     └────────┘
/agyswap-prepare   /agyswap-observe   /agyswap-spec      /agyswap-plan      /agyswap-build     /agyswap-test      /agyswap-review    /agyswap-prepare   /agyswap-commit    /agyswap-ship
```

- Each skill writes its result to `architecture/<VERB>.md`, exactly one file per verb: never split a verb into several files (for example `SPEC-<module>.md`); modules become sections inside the one file. Every skill header repeats the same order; keep the diagram, the headers, and this list in sync when the cycle changes.
- PREPARE runs twice: at the start to sync the repo before work, and after REVIEW to clean up before COMMIT. SHIP is always last, because a release needs a committed, pushed commit with green CI; it starts only when `git status` is clean. Skills other than `/agyswap-commit` never commit unless the user asks.
- `/agyswap-observe` runs before any feature that depends on agy's behavior, and again whenever `agy --version` changes. Spec, plan, and build follow `architecture/OBSERVE.md`; nothing about agy is guessed.
- Six core skills (spec, plan, build, test, review, ship) are forks of `addyosmani/agent-skills` at commit `1401c8b`. Each `SKILL.md` has an agyswap section on top, then `# Method` vendored from the upstream skill (`spec-driven-development`, `planning-and-task-breakdown`, `incremental-implementation`, `test-driven-development`, `code-review-and-quality`, `shipping-and-launch`), then `# Reference` with the inlined checklists. The agyswap section wins whenever they conflict. The three-reviewer fan-out (`code-reviewer`, `security-auditor`, `test-engineer`) comes from upstream's `.claude/commands/ship.md`, which is not vendored. In agyswap it runs in `/agyswap-review`, not in `/agyswap-ship`. A review before a release covers everything since the last tag, and `/agyswap-ship` only checks, versions, and hands the user the tag commands.
- When the user runs a skill, do every step exactly as written, even if it looks unnecessary. Skip a step only when the skill itself says to.
- Each skill folder holds only one `SKILL.md`. Edit skills only in `skills/`, never through the symlinks. The vendored parts must track upstream HEAD: `uv run python scripts/skills.py` re-vendors `# Method` and `# Reference` and updates the commit hash here and in each skill, leaving the agyswap section untouched. `/agyswap-prepare` runs it every time, and `.github/workflows/skills.yml` fails weekly (`scripts/skills.py --check`) when skills/ falls behind. Never edit the vendored parts by hand.
- `.claude/` and `.agents/` only hold local symlinks and are gitignored. How to create them is in `CONTRIBUTING.md` ("Agent Tooling"); update it when adding a symlink or MCP server.
- `docs/` is the offline copy of the official docs. Read it before using Textual, Rich, or pytest APIs, and do not invent APIs that are not there. Never edit it by hand; rerun `uv run python scripts/docs.py` when a version in `uv.lock` changes. Each file pairs 1:1 with a gitmcp server in `.mcp.json` (`textual`, `rich`, `pytest`); adding or removing one means adding or removing its pair, including the entry in `scripts/docs.py`. gitmcp reads the default branch; when it differs, `docs/` is right.
- MCP servers are edited only in `.mcp.json`; `.agents/mcp_config.json` is a symlink to it. All servers are stdio (`bunx --bun mcp-remote@0.14.3 <url>`), the only shape both Claude and Antigravity accept.
- After `graphify update .`, relabel communities with `graphify label . --backend=gemini`; `update` resets community names. The Gemini backend sometimes leaves file names (`cli.py`, `README.md`) as labels, and `--missing-only` does not treat those as missing; rerun with `--backend=claude-cli` in that case.
- Skill reports separate **findings** (broken or risky code, undecided questions; only these go to `TODO.md`) from **manual checks by the user** (things only provable with real accounts).
- Commits follow `/agyswap-commit`: split by category, English, no co-author trailer.
